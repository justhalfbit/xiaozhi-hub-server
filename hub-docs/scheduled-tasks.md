# 普通提醒与动态定时任务

“提醒我取快递”只需要在约定时间播放固定提醒；“到点播报当天天气”则需要执行时查询。创建阶段由当前对话模型理解语义，选择设备的 `self.alarm.create(kind=reminder)` 或 `self.task.create`，不通过匹配用户文字中的关键词分流。例如“提醒我看看新闻”仍是固定提醒，“给我播报当天新闻”才是动态查询。普通提醒触发时继续使用设备缓存语音，不调用模型。

配套客户端必须暴露两类创建工具。`core.agent.scheduled_policy.with_policy` 仅在两者同时可用时加入本轮系统指导，兼容原生工具名和下划线工具名，不修改持久聊天历史。缺少执行钟点或意图不明确时先澄清，不提前查询；判断重复前先读取设备当前列表，不能依赖已过时的历史确认。

## 执行接口

设备在到点时调用 `POST /kiosk/tasks/run`：

```json
{"device":"example-device","run_id":"example-occurrence","instruction":"查询执行当天的天气并简短播报","tools":["get_weather"]}
```

响应包含 `ok`、`text`、`sources`、`executed_at`。`instruction` 长度为 1–1000，`tools` 只允许 `get_weather`、`web_search`，纯内容生成用空列表。模型只能提取查询参数和总结证据，不能调用任意设备、命令或再次创建任务。执行时间由服务端生成；上下文独立于日常聊天，不读取聊天历史。

天气沿用上游现有提供方与所在地配置，只为本次执行绕过报告缓存，普通对话的缓存行为保持原样。联网搜索复用已配置搜索服务；失败作为失败返回，不能被解释为“没有优惠”等业务结论。来源链接保存在执行结果中。

`POST /kiosk/tasks/cancel` 使用同一 `device` / `run_id`，只取消对应执行。短时取消记录处理取消请求先于执行请求到达的情况。接口仅允许设备本机直接请求，不接受代理转发；网关与客户端需同机部署。现有管理鉴权与其他 `/kiosk` 接口行为不变。

每次仅执行一个任务，总限时 120 秒；单次模型 HTTP 请求限时 45 秒。采用设备当前选择的 OpenAI 兼容 API 模型，未配置或选择 CLI / Grok Bot 模型时明确报错，不自动切换其他模型。查询/生成成功后优先输出短摘要，过长时仅压缩一次，最大保留 1200 字；客户端按不超过 200 字的片段合成播报。模型及搜索调用使用既有账户，按相应服务计费。

## 验证与兼容

专项测试使用虚拟配置和网络替身，不需要账号或 API Key，覆盖语义指导注入、历史隔离、白名单、天气缓存绕过、查询失败、来源保留、超时恢复及执行取消。还应联动配套客户端，人工验证普通提醒、动态查询、停止和重启后的持久化。硬件与真实服务验收不能由这些模拟测试代替。

本改动不修改默认配置、依赖或发布版本。需要配套客户端的任务工具和执行器；旧客户端没有两类能力时不会注入新指导。客户端 PR 在关联 PR 中给出。
